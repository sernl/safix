## Why

Enrolling a YubiKey today is a hand ceremony: provision PIV access with ykman, generate the age identity under the plugin's TTY prompts, append the identity block, edit `recoveryRecipients`, regenerate the policy, re-wrap, register with clan, and prove nothing.
The operator has now performed it twice — both fleet keys carry identities — and the dotfiles `one-unlock-bootstrap` design records what the ceremony still leaves open: the decrypt proof against the real store has never been run, and every step lives in no tool.
The operator's direction is that safix owns this: plug in a key, and everything that can be automated is, with a touch as the ceiling of required interaction and PIN, PUK and management key generated by safix rather than invented by a human.

Research at the pinned revs established the exact automation boundary.
Everything ykman does is non-interactive (PIN, PUK, protected on-card management key, enumeration by serial).
`age-plugin-yubikey --generate` is the one step that reads a PIN from a terminal only — no flag exists — so safix drives it under a pseudo-terminal, feeding the PIN it generated; a touch remains, and should: it is the property being bought.
age tries software identities before plugin identities, so an enrolled card changes nothing about ordinary decrypt cost.

## What Changes

- A new verb, `safix enroll`: detect the connected key (one at a time, or `--serial`), provision PIV access when the card is factory-fresh — safix-generated PIN and PUK, management key random and PIN-protected on-card, never stored anywhere — generate the age identity in the first empty retired slot under a pseudo-terminal, append the identity block to the same `keys.txt` `keygen` appends to, add the recipient to the person's `recoveryRecipients`, regenerate the policy, re-wrap, and commit.
- Enrollment ends with a decrypt proof or it has not ended: the card alone — an identity file holding only its stub — must open a governed file in the person's audience, exercising the PIN and the touch. This closes the gap `one-unlock-bootstrap` names.
- The generated PIN and PUK land in the root of trust: written to the session's Secret Service when the KeePassXC database is unlocked, else through `keepassxc-cli` with one password prompt; optionally also as a safix secret readable by the person's other recipients.
- Backup keys are the same verb run per key: each card gets its own identity and its own recipient, every enrollment is additive, and nothing ever removes or replaces a recipient.
- When a clan is declared, the recipient is registered through clan's own command, and `flake.safix.enrollHook` receives the person, serial and recipient for consumer-specific wiring — the same delegation and hook shape `adduser` already has.
- Hard refusals: no OTP slot is ever written — a programmed challenge-response slot guards a database whose loss is total, and the refusal names that; enrollment refuses without a terminal; the primary `recipient` stays software-only, exactly as today.
- **BREAKING** for nothing: every existing verb and every existing declaration is untouched.

## Capabilities

### New Capabilities

- `hardware-enrollment`: what `safix enroll` provisions, generates, wires, stores, proves, and refuses.

### Modified Capabilities

None.

## Impact

Affected code:

- `crates/safix-core`: the enrollment module — ykman drive (non-interactive), plugin drive (pseudo-terminal), identity-block append (sharing `keygen`'s file discipline), `recoveryRecipients` edit and commit (sharing `adduser`'s), the proof, and the refusals.
- `crates/safix`: the verb, its usage contract, the touch/insert prompts surfaced to the operator.
- `modules/flake/safix`: `enrollHook` beside `onboardingHook`.
- `README.md` and `CHANGELOG.md`, per the standing rule.

Dependencies: `ykman` and `age-plugin-yubikey` resolved the way runtime tools already are; `pcscd` active is a host precondition the refusal names when absent.
Ordering: independent of `adopt-generator-sandbox` and `settle-clan-vars-parity`; the KeePassXC write path is shared with `add-keepassxc-sync` and whichever lands second reuses it.
The fleet's two keys are already enrolled by hand; this change automates the executed trace, and its first real run is the third key or the next user.
